DESIGN RULES
1. Fixed root: 01_STRATEGY, 02_INVESTMENTS_AND_PROGRAMS, 03_INSTITUTIONAL, 99_ARCHIVE.
2. Core programmatic themes are Education and Democracy. Cross_Thematic is used only where explicitly defined (including Exploration, selected In-house Programs, Learning/External Knowledge, and related Archive paths).
3. Strategic focus (ECE, K12, Future of Talent, People in Government, etc.) is metadata, not a mandatory physical path.
4. One object = one official folder.
5. Pipeline stage changes do NOT move the organization folder. Sourcing, Screening, and Diligence are subfolders inside it; current stage/status is recorded in the Master Registry / CRM.
6. Investment Process v2 alignment: Concept Review is a project-level gate inside Screening. Investment Committee is a project-level gate inside Investment Due Diligence. Their materials stay with the project, not in central Governance.
7. Approval: move the entire Pipeline object folder once to Portfolio; retain Pipeline history; add Portfolio operating folders.
8. Decline/withdrawal: move entire object to 99_ARCHIVE/01_Declined_Pipeline and keep its Master Registry record/link.
9. Venture graduation: move the complete folder to Portfolio when it becomes an external active investment; to In-house Programs when ver+ becomes the stable operator; or Archive if closed.
10. Master indexes: maintain ONE 00_Master_Registry. Other indexes are automated views; they are not separate manually maintained databases.
11. Every Portfolio, Venture Building, and In-house object gets Photos_and_Videos.
12. Use shortcuts/links instead of duplicate final files.
13. Policies live in 03_INSTITUTIONAL/00_POLICIES. RADAR is one organizational policy; do not create a separate RADAR_SYSTEM folder.
14. Charity is a separate Transversal Area, not a Legal subfolder.
15. External third-party reference material lives in 05_EXTERNAL_KNOWLEDGE; ver+-produced research/learning lives in 03_RESEARCH_AND_LEARNING.
16. Reusable MEL systems, methodologies, standard instruments, indicator frameworks, and organization-wide MEL guidance live in 03_INSTITUTIONAL/02_TRANSVERSAL_AREAS/MEL, not in Research and Learning.
17. Do not auto-create detailed Transversal Area subfolders beyond the canonical minimum until area owners validate them.
18. 0A_EXPLORATION is a pre-Pipeline staging area for substantive contacts, topic/issue explorations, and possible opportunities that are not yet formal Pipeline objects. Use Education, Democracy, or Cross_Thematic.
19. If an exploration becomes a formal investment opportunity, create the canonical Pipeline organization structure and transfer the relevant exploration material into it; do not keep duplicate official homes.
20. Standard empty folder structures should be created through the RADAR Drive Finder > Create structure workflow rather than by manually rebuilding or attempting to duplicate folder templates.
21. Weekly email packages have a central institutional home in 03_INSTITUTIONAL/01_GOVERNANCE_AND_DECISIONS/05_Weekly email; source documents keep their official home and are linked rather than duplicated.

0A_EXPLORATION - OPERATING RULE
Path: 02_INVESTMENTS_AND_PROGRAMS/0A_EXPLORATION/[Education|Democracy|Cross_Thematic]
Purpose: preserve substantive pre-Pipeline work that is worth institutional memory but has not yet become a formal investment opportunity.
Use for: early meetings/Granola notes, concept notes, topic or organization explorations, background material, and other substantive exploratory work.
- Very light contacts can remain as a Master Registry / Opportunity Map record without a dedicated folder.
- If an exploration becomes a formal Pipeline opportunity, use Drive Finder > Create structure to create the canonical Pipeline organization folder and transfer the relevant exploration material into that official folder.
- Do not keep a second official copy in 0A_EXPLORATION after the formal Pipeline object exists.

MASTER REGISTRY - RECOMMENDED MINIMUM FIELDS
- Object_Name

- Object_Type [Exploration|Pipeline|Portfolio|Venture_Building|In_House_Program]
- Current_Stage_or_Status
- Country_or_Geography
- Owner
- Official_Folder_Link
- Last_Updated
- Optional: Decline_or_Closure_Reason; Decision_Link

AUTOMATED VIEWS FROM 00_Master_Registry
- 01_Opportunity_Map: all known explorations/opportunities/organizations, including declined/closed where useful.
- 02_Active_Portfolio: Object_Type=Portfolio and active status.
- 03_Ventures_and_In_House_Programs: Object_Type in {Venture_Building, In_House_Program} and active status.
- 04_Archived_and_Declined: declined/closed/archived status.
Human action determines status/type. Automation updates views and folder links; it does not infer investment decisions from file contents.

MEETING RULES
- Every organization/venture/in-house program has 01_Meetings for relationship/working history.
- Create one living yearly log: YYYY_[Object]_Meeting_Log.
- Raw Granola/AI notes go under Raw_Notes/[Year] with a dated name.
- Concept Review is stored with the project in Screening.
- Investment Committee is stored with the project in Investment Due Diligence.
- Central Governance is only for Board, Leadership Team, All Team, and Offsites.
- Decision Log is an index; it does not replace minutes, gate records, or the object Meeting Log.

EMPTY STRUCTURE CREATION RULE
Google Drive does not support duplicating a folder template into the same location in the way RADAR users would need. Folder templates in Drive are therefore references; standard new structures should be generated with the RADAR tool.
Workflow:
1. Go to the Employee Hub and open the RADAR microsite.
2. Open the Drive Finder from the link at the top of the page.
3. Sign in with your VélezReyes+ Google account.
4. Select the Create structure tab.
5. Accept the additional Google Drive permissions if prompted.
6. Choose the structure type and follow the guided steps (Details > Preview > Confirm > Result).
Current structure types shown in the tool:
- Pipeline organization
- Venture Building initiative
- In-house program
- BecaTech+ partner or provider
- Policy
- Formal governance meeting
- Annual OKR cycle
Portfolio note: do not create a separate Portfolio object from scratch. When a Pipeline organization is approved, follow the Portfolio Creation Rule: move the existing Pipeline folder to Portfolio and add the Portfolio operating subfolders while preserving history.
Emergency Response note: use In-house program and the Cross_Thematic location for Emergency_Response.
